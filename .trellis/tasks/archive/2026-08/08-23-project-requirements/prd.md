# 编码评测基准任务套件（父任务）

## Goal

产出**多份可交付给其他 AI 实现的全栈编码评测任务规格**，用于评测目标模型的编码能力。每份任务规格独立交付、页面肉眼可见验收、**改动不入库**。

当前需求池：
1. 知识库概览仪表盘（全栈：新后端统计端点 + 前端概览页 + 单元测试）→ 子任务 `08-23-dashboard`
2. 设置界面 LLM 配置重构（前端重构 + 小后端改动：服务商预设模板 + 默认表单 + test 端点 `profile` 参数）→ 子任务 `08-23-settings-llm-rework`

## 共同约束（所有子任务）

- **页面肉眼可见**：功能落地后打开前端页面（或截图）即可看出效果。
- **可目视验收**：验收以"页面上观察到什么"为准，辅以单元测试兜底。
- **自包含**：另一 AI 拿到该任务需求 + 可运行环境即可动手，无需深度背景。
- **不入库**：本次改动不提交、不并入项目（本机验证后丢弃或隔离）。
- **环境**：Library v0.3.6；后端 `library serve`（127.0.0.1:8000）、前端 `desktop/` `npm run dev`（127.0.0.1:5173，`/v1` 由 Vite 代理）。

## 任务地图

| 子任务 | 方向 | 交付物 | 验收口径 |
|---|---|---|---|
| `08-23-dashboard` | 知识库概览仪表盘 | 后端只读 `GET /v1/stats/overview` + 前端「概览」页 + 单测 | 页面显示与库一致的真实统计；单测全过 |
| `08-23-settings-llm-rework` | LLM 配置重构 | 前端服务商预设模板 + 默认表单 + 高级折叠；`POST /v1/settings/llm/test` 加可选 `profile` 参数 | 页面选预设→填 key→测试（只测默认）→保存，状态可见 |

- 各子任务有独立的 `prd.md` / `design.md` / `implement.md`。
- 子任务之间**互不依赖**，可分别交付、分别验收。

## 交叉验收（父任务）

- [ ] 两份基准任务规格各自完整、自包含，可直接转交目标 AI。
- [ ] 每个规格的验收标准可目视判断，且不依赖目标 AI 无法获得的外部信息。
- [ ] 每个规格都明确"改动不入库"。
- [ ] 父任务集成评审：任务地图与实际工件一致，无孤儿/错位。

## 开放问题
